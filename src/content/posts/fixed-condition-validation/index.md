Shader 工具容易制造一种假象：脚本运行成功、节点数量正确、材质链接存在，于是“复刻完成”。但节点存在只说明结构被创建；法线空间、遮罩极性、光照顺序和最终画面需要各自的验证。

有诊断价值的验证，需要让每次比较只改变一个主要变量，并且能回到中间输出。

![固定条件验证架构](./images/validation-architecture.png)

## 1. 先冻结所有不想比较的东西

验证合同至少应写明：

- Blender 版本和渲染器；
- 场景、相机、焦距和裁剪；
- 模型形态、姿态、动画帧和 LOD；
- 主光、本地灯、世界光和阴影设置；
- 分辨率、采样、曝光和色彩管理；
- 随机种子、时间和动态 FX 状态；
- 输出格式、颜色空间和差分方式。

如果这些信息没有冻结，A/B 结果只能说明两个实验不同；目标变量是否造成了变化，需要冻结后的对照。

## 2. 用阶段接触表取代只看最终截图

每个模块至少导出：

| 阶段 | 输出 |
| --- | --- |
| 输入 | Base、Normal、Mask、UV、Alpha |
| 材质中间值 | Ramp、SDF、区域、方向、高光带 |
| 几何层 | Outline coverage、Fur shell、深度 |
| 合成前 | Toon 结果、反射/环境输入 |
| 最终 | Scene Color、显示变换后的预览 |

这样可以回答“错误从哪一步开始”。如果最终脸部偏暗，但 SDF 和 Ramp 已经正确，问题可能来自灯光方向、色彩管理或后续合成；Face Texture 的调整放在这些检查之后。

![固定条件结果预览](./images/fixed-view-preview.png)

## 3. 单变量 A/B 的例子

### 法线 A/B

只切换 Normal Map，保持 Base、灯光和相机不变。观察第一处变化是材质中间值、轮廓覆盖还是最终亮度。

### SDF A/B

只切换 SDF 左右方向或关闭 SDF。若整个脸的分档都改变，说明它确实进入主链；若只改变一小块区域，则需要进一步确认 mask。

### 轮廓 A/B

只关闭 Geometry Nodes 轮廓壳。若表面颜色和深度关系也改变，说明轮廓层可能写入了不应写入的目标或影响了排序。

### 高光 A/B

分别关闭方向场、区域 mask 和高光 Ramp。这样可以判断高光位置、形状和颜色分别由谁负责。

## 4. 差分要和显示变换分开

中间值在线性空间保存，在相同显示变换后再制作阅读用接触表。不同曝光、不同 Gamma 或不同色调映射后的图直接做绝对差没有意义。

可以记录：

- 变化像素比例；
- 平均绝对误差；
- 高分位误差；
- 最大通道差；
- 误差集中在哪些材质角色或屏幕区域。

指标不能代替人眼，但能帮助定位“是整体偏移，还是边缘局部错位”。

## 5. 结构回归也很重要

视觉验证之外，还应做：

- 重复 Apply 两次，比较节点/材质结构；
- 新进程打开文件，检查外部资源和驱动；
- 关闭所有生成模块，确认原始链接能恢复；
- 重新渲染固定机位，确认输出稳定；
- 检查所有图片链接和 alt 文本。

如果第二次 Apply 多出一套节点，或者回滚后仍残留几何层，后面的视觉差异就不再可信。

## 6. 结论的表达形式

一篇技术博客可以把结果写成：

1. 直接观察到的事实；
2. 当前最强解释；
3. 仍然存在的替代解释；
4. Blender 中采用的近似；
5. 固定条件下的验证结果；
6. 下一步需要补的证据。

这比单独放一张“最终效果很像”的截图更有长期价值。读者能知道哪些部分可以直接借鉴，哪些部分仍需要根据自己的模型和材质 Profile 重新校准。

固定条件验证的目标是让每一次失败都能定位下一步该查材质、几何、光照还是合成。
